## 网安必备知识

> 一些网安必备知识。



###  一、网络安全法

```shell
核心与制度：

    等级保护制度：网络运营者必须落实网络安全等级保护，留存网络日志不少于6个月。

    实名认证要求：为用户办理网络接入、域名注册或信息发布时，必须要求提供真实身份信息。

    关键信息基础设施保护：对重点行业实施重点保护，要求境内存储重要数据并开展定期检测评估。

    个人信息保护：收集和使用个人信息应当遵循合法、正当、必要原则，严禁非法泄露或篡改
```



### 二、渗透测试流程：



### 1. 前期准备与授权 (Pre-engagement Interactions)

在展开任何技术操作之前，必须先明确法律边界与测试范围，避免合规风险。

- **明确目标与范围：** 确定测试的具体域名、IP 范围、API 接口、目标应用等。明确哪些系统属于禁止测试的“黑名单”。
- **确定测试模式：**
  - **黑盒测试（Black-box）：** 零背景信息，模拟真实外部黑客攻击。
  - **白盒测试（White-box）：** 提供架构图、源码、凭据等，用于深度代码审计与系统打靶。
  - **灰盒测试（Gray-box）：** 提供部分信息（如普通用户账号），测试内部越权与提权。
- **签署法律文件：** 签署授权委托书、保密协议（NDA）及测试时间窗口约定，明确紧急联络机制。



### 2. 信息收集与侦察 (Reconnaissance)

信息收集的广度直接决定攻击面的大小。

| **收集维度**           | **主要技术与目标**                                           |
| ---------------------- | ------------------------------------------------------------ |
| **被动收集 (Passive)** | 利用 OSINT（公开来源情报）、Shodan/FOFA 资产搜索引擎、Whois 查询、GitHub 敏感代码泄露检查，不直接与目标产生直接交互。 |
| **主域名与子域名**     | 使用 Subfinder、Amass、OneForAll 等工具进行子域名爆破、DNS 爆破与 CNAME 剖析。 |
| **端口与服务识别**     | 利用 Nmap、Masscan 扫描目标开放端口（如 80, 443, 22, 3306 等），识别具体的服务版本（如 Apache httpd 2.4.49）。 |
| **Web 架构指纹**       | 使用 Wappalyzer、WhatWeb 探测前端框架（Vue/React）、后端语言（Node/Python/Java）、中间件及 CMS 系统。 |
| **目录与接口泄露**     | 使用 ffuf、dirsearch 对 Web 目录、Swagger API 接口文档、备份文件（`.git`、`.tar.gz`）进行扫描。 |

### 3. 漏洞分析与威胁建模 (Threat Modeling & Vulnerability Analysis)

根据搜集到的信息，分析潜在的安全缺陷。

- **已知漏洞比对：** 针对识别出的服务版本，在 CVE 数据库、Exploit-DB 中匹配已公开的漏洞（如 RCE、Deserialization、SQLi 等）。
- **Web 漏洞扫描：** 使用 AWVS、Xray、Burp Suite 等自动化工具对 Web 应用进行盲扫与初步筛查。
- **逻辑漏洞梳理：** 梳理业务逻辑链条，重点关注登录注册、支付流、密码找回、权限校验等核心接口。



### 4. 漏洞利用 (Exploitation)

将分析出的漏洞转化为实际控制权，验证漏洞的真实可利用性。

- **OWASP Top 10 漏洞利用：**

  - **注入攻击：** SQL 注入（提取数据库）、命令注入（执行系统指令）。
  - **越权访问：** 水平越权（查看他人数据）、垂直越权（低权限操作管理员功能）。
  - **文件上传/包含：** 绕过前端/服务端校验上传 WebShell 或包含恶意本地/远程文件。
  - **SSRF（服务端请求伪造）：** 利用内网访问权限探测内网敏感服务。

- **POC/EXP 编写与验证：** 使用 Python 或 Metasploit (MSF) 编写针对性攻击脚本，获取 WebShell 或系统级 Shell。

  

### 5. 后渗透阶段 (Post-Exploitation)

在获取初始访问权限后，进一步评估漏洞可能造成的危害深度。

- **提权 (Privilege Escalation)：** 针对操作系统或容器环境，通过内核漏洞、SUID 提权、配置错误或不安全的定时任务，将权限提升至 `root` 或 `SYSTEM`。
- **权限维持 (Persistence)：** 建立持久化通道（如添加反弹 Shell 定时任务、植入 Backdoor、创建隐藏账户等，*测试结束后必须清除*）。
- **内网横向移动 (Lateral Movement)：**
  - 读取内存凭据（如 Mimikatz、LSASS 导出）或本地配置文件中的明文密码。
  - 代理/隧道技术（使用 FRP、Chisel、SSH 隧道）搭建内网转发通路。
  - 在局域网内进行 ARP/域控探测，对其他内网主机发动攻击。
- **数据影响评估：** 在不破坏数据完整性的前提下，证明敏感数据（如用户 Personal 数据、数据库资产）面临的泄露风险。



### 6. 痕迹清理 (Clean-up)

测试完成后，必须恢复目标系统至初始状态，防止留下的后门被恶意第三方利用。

- 删除上传的 Webshell、攻击工具、日志文件和临时测试文件。
- 清理测试过程中创建的临时测试账号、改动过的配置文件。
- 恢复被修改的数据库测试记录。



### 7. 报告编写与复测 (Reporting & Remediation)

将技术测试过程转化为高层管理者与开发人员可读的文档。

- **报告内容：**
  - **执行摘要：** 面向管理层，汇总整体安全姿态、高危风险占比与整体影响。
  - **漏洞详情表：** 详细记录漏洞类型、CVSS 评分、受影响组件、详细复现步骤（包含 Payload 与截图）。
  - **修复建议：** 针对每个漏洞提供代码级或架构级的具体修复方案。
- **漏洞复测 (Retesting)：** 待客户完成修复后，对漏洞点进行二次验证，出具最终版的复测闭环报告。
